## 2. 舵机驱动API与单位

[手册PDF第215页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=215)～[手册PDF第217页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=217)给出 `serial` 与 `uservo.UartServoManager` 的接口说明；下面是手册语义，当前封装类仍以实际SDK为准。

| API | 输入 → 处理 → 输出 |
|---|---|
| `UartServoManager(uart,is_debug=True)` | 已打开的串口 → 建立舵机管理器 → 管理对象 |
| `ping(servo_id)` | ID → 在线查询 → is_online |
| `query_servo_angle(servo_id)` | ID → 查询单圈/多圈舵机角 → 原始角度，示例单位° |
| `set_servo_angle(servo_id,angle,...)` | 目标角°、interval毫秒、velocity度/秒、t_acc/t_dec毫秒、power毫瓦 → 下发舵机控制 → 手册表写无输出 |
| `wait(timeout=None)` | timeout毫秒 → 等待舵机到达 → 手册表写无输出 |
| `set_damping(servo_id,power=0)` | 舵机ID/功率 → 阻尼模式 → 无输出；不等同于本项目新鲜角度反馈hold逻辑 |

手册舵机底层的interval单位是ms；当前Notebook末端接口 `set_tool_pose(...,T=1.5)` 的T按原程序为s，不能直接相互替换。PDF没有完整定义当前封装的set_tool_pose/gripper_open/gripper_close/trajectory_callback_period；现已补充实际SDK源码：软运动分支末尾没有显式成功返回，回调周期默认20个轨迹步；接口细节见[新增SDK核对](新增SDK核对.md)。

## 3. 关节标定关系

[手册PDF第226页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=226)～[手册PDF第230页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=230)给出两标准姿态、计算函数calc_kb与config.py中的JOINT2SERVO_K/B。关系为：

`a_i = k_i·θ_i + b_i`

`k_i = (a_iA-a_iB)/(θ_iA-θ_iB)`，`b_i = a_iA-k_i·θ_iA`。

其中a为舵机原始角度（°），θ为标准关节角（rad），k单位°/rad，b单位°，A/B为两次标准姿态。k非零且标定有效时，反馈换算为 `θ_i=(a_i-b_i)/k_i`；应先换到同一单位与坐标约定再比较误差。

手册示例标准姿态A为θ=[0,-π/2,π/2,-π/2,0,π/2]，B=[π/2,0,0,0,π/2,0]，按其标定六通道顺序。第一周报告两组原始数据中第5通道均为3.1°，若套用手册预期的0→π/2标准姿态，则k5会为0，说明该通道样本不能建立可逆映射；这解释了应复核摆位/采样的具体原因，不生成替代标定值，也不覆盖config。

该标定与week4 `z_error_polyfit.txt` 的径向高度修正 `z_adjusted=z+K·sqrt(x²+y²)+B` 是两种不同校准，不能混用。

## 4. 手册Arm5DoF运动学示例

[手册PDF第233页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=233)～[手册PDF第241页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=241)的Arm5DoFKinematic使用5个姿态关节角 `[θ1,θ2,θ3,θ4,θ6]`；这里θ6是求解器第5个输入的变量名，不是舵机ID6，也不能直接认作夹爪ID5。新增SDK确认θ6对应五姿态轴列表的joint5/舵机ID4，夹爪left_gripper_joint单独对应ID5；与ROS教学模型的轴映射仍待现场验证。

示例几何常数（手册明确注明仅供参考）：D1=70.00、A1=0.00、A2=80.00、A3=76.15、A4=185.40，单位mm。本文不将这些数值回写现有Notebook、URDF或实物标定。

令θ23=θ2+θ3，θ234=θ2+θ3+θ4，径向距离ρ=A1+A2·cosθ2+A3·cosθ23+A4·cosθ234，则：

`x=ρ·cosθ1`，`y=ρ·sinθ1`，`z=D1-A2·sinθ2-A3·sinθ23-A4·sinθ234`。

`pitch=θ234+π/2`，`roll=θ6+π`，随后按示例处理周期。x/y/z是工具坐标原点在基座系中的位置（mm）；pitch/roll是该求解器的姿态约定（rad）。

逆解先由roll得到θ6、由pitch得到θ234，再枚举θ1=atan2(y,x)及其反向候选，x=y=0时沿用上次基座角。对每个合法θ1，设：

`b1=cosθ1·x+sinθ1·y-A1-A4·cosθ234`，`b2=-(z-D1)-A4·sinθ234`，
`c3=(b1²+b2²-A2²-A3²)/(2·A2·A3)`。

当|c3|>1则不可达；否则枚举 `θ3=atan2(±sqrt(1-c3²),c3)`，再算 `θ2=atan2(b2,b1)-atan2(A3·sinθ3,A2+A3·cosθ3)` 与 `θ4=θ234-θ2-θ3`，逐轴限位过滤后返回候选解列表，空列表表示无可行解。各θ为关节角，b1/b2为扣除基座与末段影响后的平面坐标，c3为肘关节余弦。当前week4调用签名与这类接口一致；部署库的参数及实现仍需恢复后比对。

## 5. 不能混接的接口与模型

手册概述称“六自由度机械臂”，第5.8节先介绍通用6-DOF DH表，随后列Arm5DoF求解代码；第5.9节及第7.13节又使用 `Arm_Lib.Arm_Device` 与 `Arm_serial_servo_write`。这些示例和当前Arm5DoFUServo不是同一套调用约定。尤其PDF第233页上半部DH表的450/570/640mm等数值，与下方Arm5DoF代码常数不是同一套模型，不能拼接采用。

[手册PDF第441页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=441)、[手册PDF第448页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=448)的Arm_Lib示例使用舵机编号1～6、直接角度与ms时间；当前uservo路线用ID0～5，姿态参数为mm/rad并带具体标定。手册存在某功能教学示例，不证明当前工程已导入或实测该功能。手册第9章MoveIt示例也不改变本项目未集成MoveIt的结论。

[手册PDF第521页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=521)～[手册PDF第525页](../../docs/references/DICE_白熊人工智能实训平台用户手册.pdf#page=525)补足URDF、launch和RViz教程，可解释标签及节点关系；当前marm包结构/参数以归档文件为准。URDF限位单位须区分类型：revolute用rad/rad·s⁻¹/N·m，prismatic用m/m·s⁻¹/N，不照搬手册对不同关节的笼统单位描述。
