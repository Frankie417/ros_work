# `arm2026_ws` 机械臂 URDF 建模项目完整讲述稿

> 适用场景：课程答辩、向队友交接项目、从零说明模型为什么这样写。
>
> 工作环境：WSL2 Ubuntu 20.04、ROS1 Noetic、Catkin 工作空间。项目根目录为 `/home/cubertzk/arm2026_ws`；Windows 资源管理器可通过 `\\wsl.localhost\Ubuntu-20.04\home\cubertzk\arm2026_ws` 打开。

## 1. 用一分钟说明项目是什么

这是一个用 **URDF + Xacro** 描述的六轴机械臂及平行夹爪模型。URDF 负责说明每个刚体 Link、Link 之间的 Joint、坐标变换、旋转轴和限位；Xacro 是 URDF 的宏语言，用来复用参数和几何代码。ROS 通过 `robot_state_publisher` 根据关节状态发布 TF，RViz 再把模型和坐标系显示出来。

本项目不是实物控制程序：没有访问串口、GPIO 或舵机，也没有向物理机械臂发送指令。它完成的是模型建模、视觉重构、ROS/RViz 加载和坐标链验证。

模型的逻辑结构始终为：11 个 Link、10 个 Joint、1 棵无环树。其中 6 个主关节是旋转关节、1 个夹爪关节是移动关节、其余 3 个是固定关节。视觉层由最初 10 个 visual 部件重构为当前 68 个 visual 基础几何体组合；**Link/Joint、碰撞、惯性、关节 origin、axis、limit 均未因视觉重构而改变。**

## 3. 从物理机械臂到 URDF 树

建模的第一步不是画外壳，而是把实物按“能否相对运动”划分为刚体和关节。

### 3.1 Link 与 Joint 的划分

- **Link**：一个在自身坐标系中视为刚体的部件，例如底座、肩部、上臂、前臂、腕部、夹爪手指。
- **Joint**：父 Link 与子 Link 的相对运动规则。例如 `revolute` 表示绕轴旋转，`prismatic` 表示沿轴平移，`fixed` 表示两者刚性连接。

本模型的主链如下：

```text
base_link
  └─ base_joint (fixed)
      └─ link0
          └─ joint1 (revolute)
              └─ link1
                  └─ joint2 (revolute)
                      └─ link2
                          └─ joint3 (revolute)
                              └─ link3
                                  └─ joint4 (revolute)
                                      └─ link4
                                          └─ joint5 (revolute)
                                              └─ link5
                                                  └─ joint6 (revolute)
                                                      └─ link6
                                                          ├─ finger_joint1 (prismatic) → gripper_finger_link1
                                                          ├─ finger_joint2 (fixed)     → gripper_finger_link2
                                                          └─ grasping_frame_joint (fixed) → grasping_frame
```

因此 `base_link` 是根坐标系，`grasping_frame` 是夹爪工作点/末端坐标系。URDF 要求一个 Link 只能有一个父关节，所以这个模型天然是单根树，不能形成闭环。

### 3.2 坐标系与 Joint 的四个关键语义

以 `joint2` 为例：

```xml
<joint name="joint2" type="revolute">
  <parent link="link1"/>
  <child link="link2"/>
  <origin xyz="-${link1_length} 0 0.0" rpy="-${M_PI/2} 0 ${M_PI/2}" />
  <axis xyz="1 0 0" />
  <limit effort="300" velocity="1" lower="${-M_PI}" upper="${M_PI}" />
</joint>
```

解释顺序应当是：

1. `name="joint2"` 是 ROS、TF、GUI 和代码中识别该关节的名字。
2. `type="revolute"` 表示它是有角度的转动关节；关节值单位是弧度。
3. `parent` 和 `child` 表示 `link2` 挂在 `link1` 上，构成树的一条边。
4. `origin` 定义**零位时关节坐标系相对于 parent Link 坐标系**的位置和姿态。`xyz` 单位是米，`rpy` 分别是绕 X/Y/Z 的滚转、俯仰、偏航，单位是弧度。
5. `axis` 在该 Joint 坐标系中定义运动轴。`1 0 0` 是 X 轴；旋转正方向遵循右手定则：右手拇指指向轴正向，四指弯曲方向为正转。
6. `limit` 给出允许的范围和能力：`lower/upper` 是下/上角度限位，`velocity` 是最大速度，`effort` 是最大力矩（对移动关节则对应最大力）。

一个很重要的表达是：**`origin` 解决“轴在哪里、零位朝向如何”，`axis` 解决“绕哪个方向动”，`limit` 解决“能动多大范围”。**

### 3.3 实际关节表

详细原始表在 `generated/model_structure.md`。主链的关键信息可以这样说：

| Joint | Parent → Child | 类型 | axis | 典型作用 |
| --- | --- | --- | --- | --- |
| `base_joint` | `base_link → link0` | fixed | 无 | 底座与回转支承的固定装配。 |
| `joint1` | `link0 → link1` | revolute | `-1 0 0` | 第一主旋转轴。 |
| `joint2` | `link1 → link2` | revolute | `1 0 0` | 肩/臂部旋转。 |
| `joint3` | `link2 → link3` | revolute | `-1 0 0` | 肘部旋转。 |
| `joint4` | `link3 → link4` | revolute | `1 0 0` | 腕部第一轴。 |
| `joint5` | `link4 → link5` | revolute | `1 0 0` | 腕部第二轴。 |
| `joint6` | `link5 → link6` | revolute | `1 0 0` | 法兰/末端旋转轴。 |
| `finger_joint1` | `link6 → gripper_finger_link1` | prismatic | `0 1 0` | 一个夹爪沿 Y 轴移动，范围 0–0.06 m。 |
| `finger_joint2` | `link6 → gripper_finger_link2` | fixed | 无 | 另一夹爪固定在当前课程模型位置。 |
| `grasping_frame_joint` | `link6 → grasping_frame` | fixed | 无 | 定义末端工作点坐标系。 |

## 4. 为什么使用 Xacro，而不直接手写纯 URDF

主文件是 `marm.xacro`，其根节点是：

```xml
<robot name="marm" xmlns:xacro="http://www.ros.org/wiki/xacro">
```

Xacro 的价值是避免重复和魔法数字。例如顶部集中定义：

```xml
<xacro:property name="M_PI" value="3.14159"/>
<xacro:property name="link2_length" value="0.14" />
<xacro:property name="link2_radius" value="0.03" />
<xacro:property name="link2_mass" value="0.8" />
```

后续可写 `${link2_length}`、`${M_PI/2}`。当连杆长度要调整时，修改一个属性即可同步更新依赖它的 Joint origin、碰撞体和惯性表达式。Xacro 经下面命令展开后才是标准 URDF：

```bash
xacro src/marm_description/urdf/marm.xacro > generated/marm.urdf
```

`generated/marm.urdf` 是检查和发布时使用的展开结果；日常应优先修改 Xacro 源文件，避免改完生成文件后下一次生成又被覆盖。

## 5. Link 内部由什么组成

每个 Link 可包含三类不同目的的描述，不能混为一谈。

```xml
<link name="link2">
  <visual> ... </visual>
  <collision> ... </collision>
  <inertial> ... </inertial>
</link>
```

| 部分 | 作用 | 本项目的处理方式 |
| --- | --- | --- |
| `visual` | 仅控制 RViz 中“看起来像什么” | 使用 box/cylinder/sphere 组合工业外观。 |
| `collision` | 碰撞检测几何 | 保留原先简洁的圆柱/盒子，未因外观重构而改变。 |
| `inertial` | 质量、质心、惯量 | 保留原质量和惯性计算宏，未改动。 |

这样做的理由是：精细外观通常不适合直接拿来做碰撞体；复杂碰撞会降低规划/仿真效率，而课程模型重点是保持原运动学和碰撞语义稳定。

### 5.1 惯性宏

文件中的两个宏是：

```xml
<xacro:macro name="cylinder_inertial_matrix" params="m r h"> ... </xacro:macro>
<xacro:macro name="box_inertial_matrix" params="m w h d"> ... </xacro:macro>
```

例如圆柱 Link 使用：

```xml
<cylinder_inertial_matrix m="${link2_mass}" r="${link2_radius}" h="${link2_length}"/>
```

宏会展开为 `<inertial>`、`<mass>`、`<inertia ixx=... iyy=... izz=...>`。这是把标准刚体惯量公式写成可复用代码，而不是逐个手算填表。

## 6. 视觉重构是如何做的

### 6.1 设计目标和边界

原模型视觉部件很少，长臂看起来接近简单圆管，夹爪也不够像常见工业夹爪。重构目标是让其更接近工业机械臂的模块化外观：底座有层次，肩/肘有端盖与侧板，手腕有紧凑壳体和法兰，末端有平行夹爪。

参考的是 Unitree Z1、UR、Franka、OpenMANIPULATOR、KUKA 等开源项目的**设计语言**，包括模块化关节、深浅双色壳体、金属灰、蓝色标识和安全色点缀。Unitree Z1 的官方 ROS1 Noetic 参考副本位于 `_reference/unitree_z1_ros_official_noetic/`；它只用于研究结构组织和外观层次，我们没有在 `marm_description` 中引用 Z1 的 STL/DAE mesh。

严格边界是：只添加/修改 `<visual>` 和材质、RViz 相机配置；不修改任何 `joint`、`collision`、`inertial`、TF 语义或主版本的 Joint 参数。

### 6.2 材质调色板

`marm.xacro` 顶部定义了 9 个命名材质：

```xml
<material name="Graphite"><color rgba="0.055 0.070 0.085 1"/></material>
<material name="PearlWhite"><color rgba="0.88 0.91 0.93 1"/></material>
<material name="Aluminium"><color rgba="0.52 0.58 0.62 1"/></material>
<material name="OceanBlue"><color rgba="0.02 0.30 0.52 1"/></material>
<material name="SafetyOrange"><color rgba="1.00 0.30 0.035 1"/></material>
```

还包括 `Gunmetal`、`ElectricCyan`、`SignalYellow`、`RubberBlack`。配色原则是深色底座/内部、白色或蓝色主体、铝色端环、少量橙黄作为状态与机械细节；安全色只作点缀，避免整体过花。

### 6.3 三个 visual 宏

为减少重复 XML，定义了三个可重用的 visual 宏：

```xml
<xacro:macro name="visual_box" params="xyz rpy size material">
  <visual>
    <origin xyz="${xyz}" rpy="${rpy}"/>
    <geometry><box size="${size}"/></geometry>
    <material name="${material}"/>
  </visual>
</xacro:macro>
```

同样还有 `visual_cylinder` 与 `visual_sphere`。调用实例：

```xml
<xacro:visual_box xyz="0 -0.027 ${link2_length/2}"
                  rpy="0 0 0"
                  size="0.036 0.009 0.076"
                  material="Aluminium"/>
```

它表示在 `link2` 自身坐标系内放一块铝色的长方体外观件。注意：这是 Link 内部的 visual origin，不是 Joint origin；它会改变外观局部位置，但不会改变 Link 之间的 TF。

### 6.4 各模块如何形成工业外观

1. `base_link`：四层同轴圆柱，依次是橡胶底垫、深色底座、金属环和青色状态环。
2. `link0`：肩部回转壳，增加上下端环和侧向橙色铭牌。
3. `link1`：上臂改为箱型承载外壳，两端保留圆柱关节端盖，加入青色/橙色装饰板和一侧深色脊梁。
4. `link2`：前臂使用矩形外壳，前后为旋转端环，外侧增加铝色脊梁与橙色细条。
5. `link3`：与前臂形成视觉呼应，蓝色主体、深色长脊和黄色细节，表现另一段受力臂。
6. `link4`、`link5`：从圆管观感变为紧凑方形腕部壳体，仍保留圆形旋转接口以表达电机/减速器位置。
7. `link6`：作为法兰与夹爪掌部，使用同轴法兰、矩形掌部和顶部标识板。
8. `gripper_finger_link1/2`：两侧采用镜像的平行夹爪指：滑台、白色夹爪壳、蓝色指端、内侧橡胶防滑垫、青色底板和橙色紧固件。这样不再像插座，而是有清晰的开口、夹持面和对称性。

重构后 visual 数量从 10 增加到 68；核心连杆依然有 9 个 collision，和改造前一致。

## 7. 主模型与课程修改版如何对比

课程版文件：`src/marm_description/urdf/marm_course_variant.xacro`。

主模型的 `joint4` 是：

```xml
<axis xyz="1 0 0" />
```

课程版的同一行是：

```xml
<axis xyz="-1 0 0" />
```

这不是把关节移动到别处，也没有改变轴线的位置；X 轴和负 X 轴是同一条空间直线。改变的是**正角度的旋转方向**：在两版输入相同的正 `joint4` 值，课程版的 `link4` 及其后代会反向转动。

现场教师要求改 axis 时，先备份文件，再只改这一项，重新生成 URDF 并在 RViz 对比。若教师要求演示限位，可修改 `limit lower/upper`；若要求演示安装位置，可修改该 Joint 的 `origin xyz/rpy`。这三类改动的影响不同，不能混淆。

## 8. ROS 是怎样把模型显示到 RViz 的

入口文件 `src/marm_description/launch/view_marm.launch` 的核心为：

```xml
<param name="robot_description"
       command="$(find xacro)/xacro $(find marm_description)/urdf/marm.xacro" />

<node name="joint_state_publisher_gui"
      pkg="joint_state_publisher_gui" type="joint_state_publisher_gui" />
<node name="robot_state_publisher"
      pkg="robot_state_publisher" type="robot_state_publisher" />
<node name="rviz" pkg="rviz" type="rviz"
      args="-d $(find marm_description)/urdf.rviz" required="true" />
```

执行链路是：

```text
marm.xacro
  → xacro 展开
  → /robot_description 参数
  → joint_state_publisher_gui 发布 /joint_states
  → robot_state_publisher 读取 URDF 和关节值
  → 发布 /tf、/tf_static
  → RViz 读取 robot_description 与 TF，绘制 RobotModel
```

因此拖动 GUI 中 `joint1` 到 `joint6` 的滑块，不是在直接“移动模型图片”，而是在发布新的 JointState；状态发布器按 URDF 的 origin、axis 和当前关节值计算整条 `base_link → grasping_frame` 坐标变换链。

## 9. 如何构建、检查和运行

在 WSL 终端中执行：

```bash
source /opt/ros/noetic/setup.bash
cd ~/arm2026_ws
catkin_make
source devel/setup.bash

xacro src/marm_description/urdf/marm.xacro > generated/marm.urdf

check_urdf generated/marm.urdf
check_urdf generated/marm_course_variant.urdf

roslaunch marm_description view_marm.launch
```

另开一个终端可观察：

```bash
rostopic echo /joint_states
rosrun tf tf_echo base_link grasping_frame
rosnode list
```

在 RViz 中将 Fixed Frame 设为 `base_link`。拖动 `joint_state_publisher_gui` 的 `joint1` 到 `joint6`，观察机械臂姿态与 `base_link → grasping_frame` TF 数值同时变化。

## 11. 推荐的答辩讲述顺序

可以直接按下面顺序口述：

1. “这是 ROS Noetic 下的 Xacro/URDF 机械臂描述包，入口模型是 `marm.xacro`。”
2. “我先按刚体划分出 base、六段主链、两根夹爪和末端工作点，共 11 个 Link，再用 10 个 Joint 连接成单棵树。”

## 12. 常见提问与简洁回答

**问：为什么不把每个外壳都做成 STL？**
答：课程目标是理解 URDF 与坐标关系；基础几何体没有外部路径依赖，易读、易改、跨平台稳定。视觉层使用多个 box/cylinder 也能表达工业模块层次。

**问：视觉加了 68 个部件，会影响正逆运动学吗？**
答：不会。正逆运动学由 Joint 的树结构、origin 和 axis 决定；visual 只影响显示。验证中已把 visual/material 去掉后比较展开 URDF，运动学相关内容保持一致。

**问：`origin` 和 visual 内的 `origin` 是同一个概念吗？**
答：写法相同，参考坐标系不同。Joint 的 origin 定义 parent 与 child Link 的装配变换；visual 的 origin 定义一个显示几何体在所属 Link 内的位置，不改变 TF 树。

**问：为什么改 `axis` 符号会改变方向？**
答：旋转轴是有方向的向量。`1 0 0` 和 `-1 0 0` 是同一轴线的反向；按右手定则，同样的正关节角会得到相反旋转。

**问：`grasping_frame` 为什么是固定 Joint？**
答：它是附在 `link6` 上的虚拟工作点，不代表额外机械活动部件。固定它可以稳定地表示末端位姿。

## 13. 交接时最重要的注意事项

- 修改主模型请编辑 `src/marm_description/urdf/marm.xacro`，不要直接编辑 `generated/marm.urdf`。
- 修改视觉后必须同步 `marm_course_variant.xacro`；两者除 `joint4.axis` 外应保持语义与视觉一致。
- 只做外观修改时，不要改 `joint`、`collision`、`inertial`；修改前在 `_backup/` 下创建带时间戳的备份。
- 每次修改后至少运行 Xacro 展开和 `check_urdf`；涉及坐标系时启动 RViz，检查 `/joint_states` 与 `base_link → grasping_frame` TF。
- Git 仓库中的 `arm2026_ws/` 是完整工作区。协作者在有私有仓库访问权限且使用各自 GitHub 凭据的前提下，执行 `git pull --ff-only origin main` 即可获取它；不应共享任何人的 SSH 私钥。
