# Micro USB 网络手势控制

这是新建的网络版本。旧 notebook、串口版程序和原报告均保留。现在只使用本机与 Jetson 的 Micro-USB 数据线形成的 USB 网络，不需要额外的电脑间串口模块。

连接结构：本机摄像头 → 本机识别与状态机 → Micro-USB 网络 HTTP → Jetson 接收服务 → 原 SDK/内部 UART → 机械臂。Jetson 到舵机的内部 UART 继续使用；本机与 Jetson 之间使用网络。

## 本机入口

双击本目录的 `start_usb_gesture.bat`，继续使用已配好的 `.venv-gesture`。

本机演练无需 Jetson。启动相机，解除停止，点击准备，One/Two/Three 选择，OK 确认。演练动作延长至 2 秒，便于在动作执行过程中摆 Five，观察动作结果变为 `interrupted`。本机演练的中断不构成机械臂制停验证。

## Jetson 准备

1. 实验箱正常供电，通过 Jetson 的 Micro-USB 数据口连接本机。
2. 本机浏览器访问 `http://192.168.55.1:8888`，进入 Jetson JupyterLab。此浏览器中的代码运行于 Jetson。
3. 在 Jetson 新建一个目录，上传同目录中的 **`receiver_usb.py` 和 `arm_interrupt.py` 两个文件**。Jetson 不需要安装 MediaPipe。
4. 关闭其他会控制同一机械臂的程序或 notebook，避免多个进程同时使用舵机串口。
5. 在 Jetson 的 JupyterLab Terminal 中进入上传目录，先启动网络演练接收端：

```bash
python3 receiver_usb.py
```

终端显示 URL、TOKEN 和 `MODE: simulation`。本机界面的地址保持 `http://192.168.55.1:8765`，复制本次 TOKEN 到令牌框，点击“连接并查询”。8888 是 Jupyter 端口；8765 是新手势接收服务端口。

连接后先解除停止，再准备。执行 One → OK，然后在 2 秒动作期间摆 Five。接收端应停止演练，动作结果为 `interrupted`，停止状态为 `held`。成功后继续验证 Two、Three。

## 真机启动

在 Jetson 终端按 Ctrl+C 结束演练服务，然后运行（路径和内部串口以现场配置为准）：

```bash
python3 receiver_usb.py --hardware \
  --sdk-dir '/home/jetson/Notebook/4.机械臂OpenCV视觉处理实验' \
  --arm-port /dev/ttyTHS1
```

接收端需要已有 SDK 的 NumPy、pyserial 及配套文件、该台机械臂的标定配置。默认 SDK 中的在线舵机 ID 为 0..5，程序会检查这六个舵机。连接不自动回零。每次接收服务重启，TOKEN 和会话编号都会变化；本机需要断开后重新连接并填入新 TOKEN。

确认本机显示 `hardware`，再解除停止、准备。先测试空载夹爪张开，再闭合；最后在有足够空间时测试回零。第一轮在缓慢动作中触发 Five，现场确认各关节实际停止后再继续后续测试。

## 手势映射

| 手势 | 操作 |
| --- | --- |
| One 只伸食指 | 选择张开夹爪 |
| Two 伸食指和中指 | 选择闭合夹爪 |
| Three 伸食指中指无名指 小指弯曲 | 选择回零 |
| OK 拇指食指成环 其余三指伸直 | 确认并执行候选动作 |
| Five 五指张开 | 中断当前动作，保持当前位置，锁定后续动作 |

选择及确认连续 3 帧且分数至少 0.70；Five 连续 2 帧通过即触发，不需要准备或 OK，在 BUSY 期间仍然有效。执行结束或被中断后，均不会自动再执行；中断后需收手、解除停止、重新准备。不要继续举着 Five 点击解除，否则会再次触发。

## Five 如何停止当前动作

1. 本机把停止请求通过独立 HTTP 连接发往 `/stop`，不排在动作执行完成之后。
2. Jetson 立刻置取消事件并使旧指令失效，动作线程在下一次轨迹写入或回调时退出，停止继续下发轨迹点。
3. 同一个动作线程依次读取各舵机当前角度，用读取的实际角度覆盖原目标，维持位置。不会调用放松/泄力模式，避免以卸力冒充停止。
4. 连续两次新鲜反馈中，各关节角度变化不超过 0.5°、且距保持目标不超过 1°时，返回反馈稳定；超时或串口错误时显示失败，并禁止软件解除停止。

界面中的“正在制停”只代表请求已经送达。`hardware` 模式下的“反馈稳定”才代表本次软件检查通过。识别、网络、Python 调度、逐个关节通信和机械惯性都会引入延迟，程序不承诺固定制停时间。

这是可中断当前动作的软件制停，不是经过认证的硬件急停。断网时无法再依靠手势送达停止指令；接收端在心跳丢失约 1.5 秒后自行中断并保持。真实碰撞风险仍应使用设备的物理急停/电源装置。

## 取证与验证

新版本的截图、CSV、事件日志保存在 `gesture_usb/results/`，不会写入串口版的结果目录。指令记录的结果包含 `done`、`interrupted`、`error`，模式区分 `local_simulation`、`simulation` 和 `hardware`。

本机执行自动回环测试：

```powershell
..\.venv-gesture\Scripts\python.exe test_usb.py
```

自动测试不驱动机械臂，也不计入实际实验成功次数。实际验收需记录 Five 的手势识别情况、停止时动作、各关节实际制停表现，以及日志中的最终状态。
