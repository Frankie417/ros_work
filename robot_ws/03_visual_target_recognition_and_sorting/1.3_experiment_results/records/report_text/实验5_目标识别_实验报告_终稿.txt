一、实验目标
1. 理解摄像头图像采集、BGR 与 HSV 颜色空间转换的基本过程。
2. 掌握 OpenCV 颜色阈值分割、Mask 生成和轮廓处理的常用方法。
3. 能够正确识别红、黄、绿、蓝四种颜色的方块。
4. 能在不同光照条件下进行 HSV 标定，记录阈值并分析光照对识别的影响。
5*. 完成手势识别拓展。本组没有走 PyTorch 训练路线，而是直接调用 MediaPipe 官方预训练手势模型，再用 21 个手部关键点的几何规则补出 Three 和 OK 两种手势。识别端跑在本机，第 7 周实验中作为机械臂的指令源实际使用，具体见 5.4。
实际完成情况：前 3 项全部完成；第 4 项分别在固定白板和白色纸质背景两种场景下，对绿、黄、蓝、红逐色标定，累计取得 28 次单方块实测记录，其中 22 次判定正确；第 5 项完成 One、Two、Three、OK、Five 五种手势的识别，并在第 7 周实验中接入机械臂，累计下发 22 条动作指令。

二、实验重点与难点
重点：BGR 与 HSV 之间的转换、HSV 阈值分割、Mask 生成与轮廓处理，以及环境光变化对识别结果的影响。
难点：不同光照、阴影和反光条件下，HSV 参数需要反复调整才能保持识别稳定。
实际做下来，卡住我们的主要是三件事：一是红色在 OpenCV 里的 H 值跨越 0 和 179 两个端点，只用一个区间总会漏掉一半；二是绿色方块放到白板背景上以后，正面的 V 值只有 40～48，沿用的 V 下限 50 把整个正面都筛掉了，只剩一条上表面；三是机械臂、手腕和地贴白线在画面里形成的伪轮廓，面积和方块是同一个量级，光靠颜色根本分不开，只能靠 ROI 和面积阈值一起压制。

5.4* 拓展实验：MediaPipe 手势识别与机械臂指令控制（week7 实测）
手势识别在本课程里并不是一个孤立的练习题，而是直接拿来当机械臂的免手操作方式。我们没有采集数据也没有训练模型，而是直接用 Google MediaPipe 官方的预训练手势分类器 gesture_recognizer.task（float16 版本，自带 21 个手部关键点和手势分类）。官方模型只能直接输出 Pointing_Up / Victory / Open_Palm 三类，为了凑齐实验要求的 5 种手势，我们又用关键点之间的比值关系补出了 Three 和 OK。识别端（摄像头 + 推理）跑在本机 Windows 上，机械臂接在 Jetson 端，两边通过 Micro-USB 网络通道 http://192.168.55.1:8765 传递指令。

2. 指令去抖与状态机（control.py）：识别结果不直接驱动机械臂，先过 3 帧一致性 + OK 二次确认，Five 连中 2 帧即制停，避免手抖反复触发。
ACTIONS = {'One': 'open_gripper', 'Two': 'close_gripper', 'Three': 'home'}class Controller:    def __init__(self, frames=3, threshold=0.70, timeout=8.0):        self.frames, self.threshold, self.timeout = frames, threshold, timeout        self.state, self.armed, self.busy, self.stopped = 'WAIT', False, False, False        self.candidate = self.last = None        self.count = self.stop_count = 0    def feed(self, label, score, now=None):        now = time.monotonic() if now is None else now        label = label if score >= self.threshold else None   # 未过阈值一律当噪声        self.stop_count = self.stop_count + 1 if label == 'Five' else 0        if not self.stopped and self.stop_count >= 2:        # Five 连中 2 帧 -> 制停            self.stop()            return 'stop'        if self.stopped or self.busy or not self.armed:            return None        if self.candidate and now - self.selected_at > self.timeout:  # 8 s 不确认作废            self.state, self.candidate = 'WAIT', None        self.count = self.count + 1 if label == self.last else 1        self.last = label        if label is None or self.count < self.frames:         # 连续 3 帧才认            return None        self.count = 0        if label in ACTIONS:            self.candidate, self.selected_at, self.state = label, now, 'SELECT'        elif label == 'OK' and self.candidate:                # OK 二次确认后执行            self.state, self.busy, self.armed = 'EXECUTE', True, False            return ACTIONS[self.candidate]        return None

六、问题与分析
项目
内容
实验中遇到的主要问题
①摄像头能打开但取帧失败；②绿色方块只识别到上表面；③上方机械臂绿色区域形成约 800 px 伪轮廓；④红色 H 在 0/179 断裂；⑤单块被拆成两个轮廓、object_count 偏大导致记录判错；⑥白色背景下四色阈值整体偏移；⑦手腕/皮肤进入画面造成多色误检。
原因分析
①旧版本对 capture.set() 强制写宽高，UVC 协商失败；②白色背景使正面漫反射加强、V 值降到 40～48，低于原 V 下限 50；③机械臂本体同样是绿色且与方块 H 接近，仅靠颜色无法区分；④OpenCV 的 H∈[0,179]，红色真值跨越首尾，单区间必然漏色；⑤二值图中方块被高光/阴影切成多块，开闭运算核 5×5 不足以连通；⑥HSV 是相对量而 V 是绝对亮度，换背景等于改变 V 分布；⑦肤色 H 在 0～20、低 S 区域易被判为红/黄。
参数调整过程
绿色：V 下限 50→35（面积 5,326→17,652 px）；红色：单区间→0–10 ∪ 170–179 双区间 bitwise_or；ROI：整幅 (0,0,640,480)→下方 (0,285,640,195) 屏蔽机械臂，最终按要求改回 None 但增加面积下限 700；形态学：开运算去噪 + 闭运算补洞，核 5×5；判据：由“有轮廓即命中”改为“颜色匹配 + 单目标 + 面积达标”。
解决后的结果
固定白板场景连续 30 帧均稳定检出红/黄/绿/蓝各 1 个轮廓；28 次真实单块记录中主目标颜色 28/28 判对，整体（含 object_count 判定）为 22/28；剩余误差全部来自同框背景伪轮廓与多手/手腕干扰，可通过 ROI + 面积上限 + 最大轮廓优先进一步压缩。
七、实验结果与总结
项目
内容
本次实验最主要的收获
最大的收获是把课本上的颜色公式真正跑成了一条完整链路：raw → HSV → inRange → 开闭运算 → findContours → boundingRect → 标签、面积和中心点。以前只知道 HSV 比 RGB 好分开颜色，这次才体会到实际调参时真正麻烦的是光照和背景。另外也养成了一个习惯：每帧同时存 raw、result、masks 三张图再配一行 CSV，出了问题能立刻回到中间结果去找，而不是凭感觉猜。主目标中心点 (cx, cy) 也直接就是后面机械臂抓取要用的像素坐标。
HSV识别注意事项
①H 在 OpenCV 里是 0–179 循环的，红色跨在两端，必须拆成两段再合并；②V 表示的是绝对亮度，换个背景或换个灯，V 的分布就变了，下限必须重新标；③阈值要给 S 留一点余量，否则阴影一压就掉出去；④只靠颜色阈值不够，面积下限和 ROI 得一起用，不然机械臂、手腕、地贴反光全都会被算进来；⑤做单块测试前一定要把其它方块移出画面，否则“只允许一个目标”这条判据必然误报。
光照变化影响分析
这次实测下来，光照主要影响 V 和 S 两个通道。白板反射让 V 从深色背景时的 99 一路升到 200 以上，同时把绿色正面的 V 压到 40～48；而强光高光会让蓝色上表面的 S 掉到 80 附近、V 冲到 255，结果主轮廓只剩暗面那一小块（见图 8 右的 blue 3834）。所以比较靠谱的做法是按场景分组标定，每次调完都用同一帧 raw 重新算一遍面积，而不是指望一套参数通吃。
后续颜色抓取任务准备
目前 detect_colors() 已经能返回 [{color, center, area, bbox}]，center 就是整幅画面里的像素中心，接上标定矩阵就能换算成机械臂坐标。后面还要补三件事：一是按最大面积只保留主目标，二是给面积加一个上限把远处的伪块滤掉，三是加静止帧一致性判断（连续 3 帧同类同位置才下发指令），避免手一抖就误抓。
手势识别与指令触发
五种手势已经在第 7 周实验里接到了机械臂上：One 张爪、Two 合爪、Three 回零位、OK 确认、Five 制停。识别侧 One/Two/Five 用的是模型分类分数，Three/OK 用的是关键点几何余量；指令侧另加了 3 帧去抖、OK 二次确认和 Five 连中 2 帧才制停。整轮实测拿到 22 条动作回执，全部返回 done，没有出现中断。
